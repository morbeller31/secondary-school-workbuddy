# Visual explanation and knowledge retention

Use this guide when a learner needs a different explanation, cannot connect concepts, or forgets previously taught material. Use visuals only when they clarify the current task; preserve independent work and one active question at a time.

## Select the representation by the learning purpose

| Purpose | Preferred representation |
|---|---|
| Observe real scientific appearance | Textbook image, verified photograph or micrograph |
| Identify structures and locations | Accurately labelled diagram alongside a real image when useful |
| Understand a changing process | Short verified animation/video segment, or a sequence of still diagrams |
| Understand cause and effect | Cause → mechanism → result diagram with labelled arrows |
| Classify concepts | Tree or concept map with named relationships |
| Compare | Aligned comparison table or paired diagrams |
| Mathematics relationships | Bar model, number line, geometry diagram or worked method; preserve numbers and units |
| English reading and writing | Story map, paragraph planner, evidence table, vocabulary map or sentence annotation |
| Humanities and Global Citizenship | Timeline, stakeholder map, cause/consequence diagram or perspective/evidence table |

## Two levels of explanation

1. **Current explanation card:** one question, one visual purpose, short labels and one open understanding check. Start with roughly 3–6 relevant elements and expand only as needed. A dense whole-unit map should not be the first explanation.
2. **Unit knowledge map:** maintain `learning-maps/<Subject>/<Unit>.md` in the private workspace. Connect new concepts to earlier concepts, keep the source reference, and record what was demonstrated independently, what required prompts, and what needs another check. Show only the relevant branch during teaching.

The complete map may grow across sessions. Keep the overview small and link to detailed cards. Treat maps as a record of learning, not an assessment score. Do not mark a concept mastered solely because the learner says they understand.

## Use external media and self-drawn diagrams appropriately

- A simple self-drawn diagram is suitable when its relationships are accurate and it is easier to read than available sources. Real appearance, anatomy, apparatus and precise scientific structures usually require verified source images or accurate schematics.
- Prefer the assigned textbook and reputable educational, scientific or institutional sources. Google Images is a discovery route: open the original page and verify the image, labels and relevance before using it. Give a short source link near external media.
- Do not invent sources, links, quotations, timestamps or claims that you inspected a video. If browsing, image display, annotation or video playback is unavailable, say so briefly and use a clear supported representation or request the relevant material.
- For annotations, preserve the source image and add legible labels and precise leader lines. Do not cover important structures. If annotation tools are unavailable, pair the original image with a numbered legend instead of claiming to have edited it.
- Before a video, give one observation question. Use a relevant short segment; provide a verified timestamp only if inspected. Afterwards ask the learner to explain, sequence or draw the process, then apply it to a different example. A video is not a substitute for checking understanding.
- Do not automatically use decorative AI images as scientific evidence. Check any generated schematic against the source before presenting it.

## Quality check before presenting

Check scientific facts, labels, arrow direction, relationships, units and notation against the available source. Use readable text, aligned elements, adequate spacing, few crossing lines and a clear reading order. Colours must have a stated meaning where needed; do not rely on colour alone. Label arrows with relationships such as “causes”, “is part of” or “next”. Inspect the rendered result when tools permit; raw Mermaid or SVG code is not a displayed visual. If the platform cannot render it, use a table, numbered layout or source image with a legend.

Ask one open question requiring the learner to explain a relationship, add a missing label, reconstruct a step or apply the idea. Do not use academic answer choices. If the response shows the diagram did not help, simplify or switch representation instead of adding more nodes to the same diagram. Record which representation helped in the parent log.

## Retention and retrieval

At the next relevant session, ask for a short recall before revealing the map. Let the learner explain, sketch or reconstruct a small part, then show the relevant branch and correct omissions. Finish with a different application when useful. Schedule another brief check at a later related lesson or weekly review according to schoolwork and demonstrated performance; do not claim scheduled reminders unless the platform actually supports them.

Use the parent log to record prompted versus independent recall. Put only confirmed errors into the existing subject error book. A concept that needs review without a confirmed error belongs in the knowledge map, not automatically in the error book. Repeated difficulties should lead to another explanation or source example, rather than an endless recall drill.
